# 文件筛选与批处理可靠性联合设计

状态：方案 A+B 已选择；用户以“完成开发”目标授权继续，进入实现与验证。

可实施性审查：独立 builder check 已完成，结论为“nothing important left”；未发现规划前仍需补充的重要问题。

## 目标与依据

优先服务 Windows 日常命令行与脚本使用，打通“筛选文件 → 批量处理 → 校验结果”。本轮联合完善 xargs 与 find 的批量执行，不增加发布命令。

现有稳定基线修复仍在当前分支中，保持原样。本设计及后续实现与已完成的基线任务分别记录；不自动推送、打 tag 或发布，不在本设计阶段改版本号。

已检查源码与本机发布二进制：

- xargs 仅 split_whitespace，`"alpha beta"` 被拆开且引号残留；只要初始参数包含 `{}` 就自动替换；`--replace={}` 按单词读取且同一参数只替换一次；没有标准 `-I` 与 `-r`。
- xargs 全量读入 stdin；默认分批只按 UTF-8 字节粗计，显式 -n 时不再检查长度；NUL 模式会丢弃空参数。
- find 为每个 `-exec … {} +` 收集全部路径，遍历结束才一次启动。现有 -exec 分支和短路表达式结构可保留。

## 方案选择

1. 仅修 xargs：变更较小，但 find 的另一条批处理路径仍可能超过命令行上限。
2. 联合修 xargs 和 find，共用命令行计量与批次边界：用户已选择 A+B；能以相同的 Windows 长度规则验证两条路径。
3. 新增统一多路复用命令或通用任务执行框架：本轮不采用，现有命令和共享 crate 足以承载。

## xargs 输入及选项

- 普通模式按 GNU 的空格、TAB、LF 分项，支持单/双引号与反斜杠的 xargs 输入规则；这不是 cmd.exe 或 PowerShell 语法。引号不进入参数，带引号的空串保留为空参数。未闭合引号、结尾不完整转义、输入中意外 NUL 明确报错，不能静默丢弃或改写。
- `-0/--null` 按 NUL 分项，内容原样保留，引号、反斜杠和 CR/LF 均无特殊含义；连续 NUL 表示空参数，结尾分隔符不凭空增加一项，EOF 前未终止的一项仍有效。
- 输入按 UTF-8 解码，中文和补充平面字符原样传给 Windows 子进程。非法 UTF-8 明确失败，不再使用有损替换去启动可能指向错误文件的命令。Windows 路径无法完整映射为 UTF-8 的情况不声明 GNU 原始字节路径兼容。
- 新增 `-I STR`，保留 `-i` 默认 `{}` 和现有 `--replace=STR` 用法。只有显式替换选项才启用替换；替换初始参数内全部标记，不把输入内容再次当作模板解析。无标记的普通参数保持字面值。
- 替换模式每条非空逻辑行执行一次，行内未引用的空格不拆项；按 GNU 处理起始空白、引号及转义。`-0` 与替换模式合用时每个 NUL 记录为一项。CR 在普通/替换输入中仍属于内容，CRLF 不自动归一化；文件路径流优先使用 `find -print0 | xargs -0`。
- 新增 `-r/--no-run-if-empty`。普通模式默认空输入执行一次，-r 跳过；替换模式空输入不执行。显式 `-n 0` 为错误。-I 后的 -n 1 保留替换模式；-I 后的 -n N（N>1）禁用替换模式并警告；-n 后的 -I 启用替换模式，忽略之前的 -n 并警告。这些组合已与本机 GNU 对照。
- 从第一个命令操作数起，后续 `-r/-n/-I` 等属于子命令参数；`--` 可显式结束 xargs 选项。空替换标记报错。
- 未指定命令时提供默认 echo 行为，不依赖 Windows 上是否存在外部 echo.exe。输出参数以空格连接并以 LF 结束。
- 输入按项读取、按批执行；工作内存随当前批次和当前输入项大小有界，不再读完整条输入流。单项超限尽早报错。子进程 stdin 接空设备，避免抢读后续输入；-p 仍单独从 CONIN$ 读确认，不改变用户 PATH 或启动交互窗口。

## 统一批次规则

在 ruxcmd-core 中新增纯计量/分批辅助模块，由两个命令依赖；不引入新的第三方依赖或共享进程生命周期框架。

- 保守批次预算为 **8000 个 UTF-16 code unit**，包括程序名、固定参数、数据参数、参数间分隔和末尾 NUL。计量按 Windows 参数引用/反斜杠转义后的上界计算，覆盖空参数、空格、双引号、尾反斜杠和非 BMP 字符；参数仍交由 std::process::Command 独立传递。
- xargs 同时遵守 -n 与长度预算；下一项放不下时先执行当前批，再将该项放入新批，不丢失、不重复。替换模式必须在完整替换后重新计量。
- 固定命令本身超限、单个输入项加固定参数超限均明确报错；不把单项截断，不悄悄突破预算。8000 是本项目保守策略，不声明支持全部 Windows 原生命令行容量。
- 不自动通过 shell 执行。用户显式选择 cmd /C 或 PowerShell 时，shell 的展开规则和额外限制仍由该 shell 决定；长度预算不能保证展开后的命令也符合限制。

## find 的 + 执行路径

- 每个 -exec 动作保持独立批次和长度状态。遍历遇到匹配路径时逐项加入，满批即执行；遍历结束后按现有表达式树顺序执行剩余批次。
- 同一动作内参数保持遍历顺序、每条匹配路径恰好处理一次；不承诺不同 -exec 动作之间的全局执行先后，也不增加目录排序。
- `+` 动作的表达式真值始终为 true；批次子进程失败使 find 最终退出 1，但继续遍历和处理其他批次。启动失败和超限也要诊断并反映在最终状态。
- 单项过长时先处理已收集的合法项，拒绝该项并继续其余路径；固定命令本身超长时该动作不执行，只诊断一次，其他动作继续。
- 保留 -exec 的分号形式、布尔短路、-print/-print0、遍历深度、删除和 reparse-point 规则，不借此修改其他已知差异。
- **明确的时机变化**：子命令由遍历结束执行改为批次满时即可执行；子命令对文件树的修改可能被后续遍历或谓词观察到。这是实现有界批处理的预期行为，文档需说明，测试不假设全局延迟执行。

## 错误与退出状态

- xargs 所有子命令成功或按规则未执行时为 0；普通非零子状态累计为 123，继续后续批次；子状态 255 返回 124 并停止后续执行；找不到程序返回 127，其他启动失败返回 126；自身读取、输入解析、编码、用法或长度错误返回 1。
- Windows 没有 POSIX 信号状态的完整等价物，本轮不伪造 125 的信号语义。已有成功批次不回滚，错误不是整条任务的事务撤销。
- find 保留整体 0/1 协议；新增批次操作的启动、执行和超限错误必须汇总。本轮不扩展修复与批处理无关的历史输出或遍历差异。

## 验证与交付

- 新增共享计量单测：UTF-16、空值、引号、尾反斜杠、固定前缀、恰好边界、单项过长。
- xargs 行为测试逐项记录真实子进程 argv、批次和状态，覆盖普通引号/转义、NUL 空参数、中文/空格、重复替换标记、字面花括号、空输入、-n 与长度同时生效、错误编码、失败子进程与缺失程序。不得只检查输出中是否含首尾几个样本。
- find 测试覆盖多批次、多个独立 -exec 动作、固定参数、零匹配、超长项、子进程失败后的继续处理，以及原有布尔短路/分号形式不变。测试专用原生 argv 记录器可在临时目录编译，不增加发布 bin 目标；具体 fixture 组织由实施者决定。
- 新增完整场景：含中文、空格及命令元字符的 fixture，经真实字节管道 `find -print0 → xargs -0 -r → cp`，再逐文件验证内容/摘要；以 `find -exec cp … {} +` 执行等价场景。空匹配不创建目标文件；超过一个批次仍完整复制。
- GNU 差分新增适用用例，明确记录 UTF-8/Windows shell 等平台差异，不扩大通配豁免。参照探测须像现有 difftest 一样引用每个参数，避免 MSYS 自动展开未引用的 `{}`。
- 场景验证纳入 Verify，并在 ZIP 解压后的可执行文件上运行；文档给出命令路径、字节管道及 PowerShell 文本管道的注意事项。同步兼容表、CHANGELOG 和迭代状态；不声明完整 GNU 兼容。
- 验收：针对性单测/行为测试、GNU 差分、全量 Verify、ZIP 解压场景验证及独立代码审查通过，再决定后续版本与发布动作。

## 本轮之外

不新增 xargs -P/-d/-L/-s/-x、find -execdir/-ok 或完整 GNU findutils 功能；不更改 shell 语法、系统级 PATH、进程树管理、其他命令实现及发布命令数量。
