# RuxCmd 发展方向与见解

**简体中文** | [English](roadmap.md)

> 撰写日期：2026-11-07。基于 v0.5.10：142 个命令、1740 项测试、当日 11 次发布、全部门禁绿。v0.5.11 为文档与进度闭环收口版本（无 CLI 变更），下列自动化与分发工作顺延至 0.5.12 / 0.6.0。
> 本文是维护者对项目现状的分析与中期方向规划，不承诺具体日期。执行记录见[迭代状态](iteration-status.md)，逐轮台账见 [.superpowers/sdd/progress.md](../.superpowers/sdd/progress.md)。

## 1. 项目定位：GNU 词汇 + Windows 语义

RuxCmd 不与 WSL 竞争，也不与 Git Bash/MSYS2 竞争。

- WSL 是完整的 Linux 环境：重、隔离、文件系统跨界。用户要一个真正的 Linux 时选它。
- MSYS2/Git Bash 是 POSIX 模拟层：路径转换、行尾、信号语义层层纠缠，脚本"看起来能跑"但行为在边界上漂移。
- **RuxCmd 的位置在两者之间**：把 GNU 命令词汇（`sort | uniq -c | head`）带给 Windows 原生进程语义——真实的 NTFS 时间戳、卷与驱动器模型、Windows 的粗粒度权限、无运行时依赖的单文件 exe。脚本"写得像 Linux"，行为"准得像 Windows"。

用户画像：在 Windows 上写脚本的人——CI/CD、运维自动化、从 Linux/macOS 迁移来的开发者、被 PowerShell 词汇贫乏困住的原生用户。他们的痛点不是"缺一个 shell"，而是"缺一套可组合、可移植、行为可预期的命令词汇"。

这个定位决定后面所有取舍：**凡是 Windows 能给出真实语义的（时间戳、磁盘计数、WTS 会话），按 Windows 语义实现并如实声明差异；凡是词汇层面的（选项、输出格式、退出码），向 GNU 逐字节对齐。**

## 2. 现状判断：项目正处在拐点

当前的质量指标领先于采用指标，而且差距还在扩大：

| 维度 | 现状 |
| --- | --- |
| 质量 | 1740 项测试、差分对照逐字节一致、Verify 门禁全绿（测试/clippy -D warnings/compat-check/check-manifests/difftest/安装脚本） |
| 功能 | 142 个命令，P0/P1 全部清零，P2 剩余项多为平台本质限制 |

| **分发** | **零**——没有 winget 包、没有公开 scoop bucket、没有文档站，安装靠手动下载 |

判断：**继续写代码的边际收益已经低于让一个人装上项目的收益。**下一阶段的乘数是分发，不是功能。这决定了下文所有主线的排序。

## 3. 核心见解

### 3.1 差分对照是本项目的方法论护城河

项目最独特的资产不是代码量，而是方法论：**对参照实现做逐字节差分**。整个会话里它反复证明自己——

- SHA256 的 `*` 分隔符、GNU 二进制模式的 NUL 分段计数、`yesterday = now−1 天`而非昨夜零点、dd 转换表——全部来自对 MSYS2 参照工具的实测探针，而不是凭文档想象。
- 同时它防止了反向错误：compat 表里的"缺口"被实测证伪过两次（sed 嵌套分组、find 相对日期早已实现）。

这条方法论要制度化：**凡声称"不支持 X"，先跑一次参照工具；凡实现"支持 X"，先构造逐字节对照用例。**没有参照工具的命令（zip、iostat、sar），自建黄金向量并在文档声明参照来源。

### 3.2 稳定性来自闭环，不来自自觉

v0.5.5/v0.5.6 的清单 SHA256 断链是本周期最重要的教训：更新脚本失败被误判成功，连续两个版本的哈希停留在旧值，用户校验安装必然失败——而没有任何门禁会喊停。

对策已经落地（check-manifests 进入 Verify、发布后强制下载 .zip.sha256 回填核对），但原则值得写下来：**任何"人保证会做"的步骤，最终都要变成"机器不做就过不去"的门禁。**发布流程里剩余的人工环节（见 4.2）都按此处理。

### 3.3 假缺口治理：清单要被探针检验

兼容性表是项目的承诺文档，但"缺口"本身也会腐化——实现前进了，文档没跟上，或者缺口从未真实存在。本轮实测证伪了两个声称的缺口。对策：缺口清单按"探针日期"管理，超过一个版本的未复核缺口自动降级为"待验证"。

### 3.4 142 个独立 exe 是取舍而非妥协

单文件原生 exe 换来：按需分发、无 PATH 遮蔽（rux- 前缀）、无运行时依赖、崩溃隔离。代价：进程启动开销 ×142、共享代码依赖 ruxcmd-core 的纪律。

这个架构不打算改，但它的成本必须**有数据地**呈现（见 4.3 性能基线）——"142 个 exe 启动慢不慢"是这个架构最常被问的问题，答案应当是一张对照表而不是一句感觉。

### 3.5 Windows 语义忠实是差异化，不是缺陷

时间戳用真实的 NTFS 字段、磁盘计数用 IOCTL_DISK_PERFORMANCE、会话枚举用 WTS——这些"不如 POSIX 精细"的地方恰恰是项目可信度的来源。POSIX 模拟层的每一条"等价"都是将来的一次行为漂移。原则：**Windows 给什么就用什么，给不了的如实写进兼容表，绝不虚构。**

## 4. 四条发展主线

### 4.1 分发与可见性（优先级最高）

| 动作 | 内容 | 量级 |
| --- | --- | --- |
| winget-pkgs 提交 | 将 scripts/packaging/winget 清单提交 microsoft/winget-pkgs 社区仓库，`winget install` 可用 | 半天 + PR 往返 |
| scoop bucket | 独立清单仓库，用户 `scoop bucket add ruxcmd` | 2 小时 |
| 文档站 | 现有双语 docs 用 GitHub Pages 发布；发布说明有固定落点 | 半天 |
| 1.0 信号 | 分发落地 + 缺口冻结后打 1.0，版本号本身成为采用信号 | — |

### 4.2 发布流程自动化收尾

剩余人工环节全部机械化：

- Release 工作流成功后自动运行"下载 .zip.sha256 → 回填清单 → check-manifests → 提交推送"（Post-release sync job）
- 失败可重入：每个发布版本一条 manifest 提交的惯例已验证可行

### 4.3 质量深化（防守性投入）

- **difftest 参数组合扩展**：sort/grep/cut 等高频命令的选项交叉组合（`-c -z`、`-k2 -r -u`），seed 固定保持确定性
- **解析器属性测试**：bc/find/awk 的语法层"任意输入不 panic、不无限循环"不变量
- **性能基线**：142 个 exe 冷启动 vs GNU/PowerShell 对照表；管道组合吞吐量
- **ARM64 CI**（可选）：windows-11-arm runner 验证可移植性

### 4.4 基建整合（还债）

三处重复实现统一进 ruxcmd-core，一次修正处处生效：

- **尺寸后缀解析**：du / truncate / dd 各持一份 K=1024/KB=1000 表
- **日期时间解析**：touch / find 各持一份（find 的相对日期语法应回流给 touch `-d`）
- **纪元换算**：zip / touch / timefmt 三处 DOS↔Unix 换算

## 5. 非目标（明确不做）

- **不继续盲扫 P2 清单**：剩余项等待真实用户反馈触发，或探针证伪后移除。
- **不做字节级归档布局对齐**：zip 无参照工具，投入无底洞；语义级一致已足够。
- **不实现平台本质不可能项**：mktemp 的 Unix 权限、mkfifo 的持久 FIFO 等保持声明差异。
- **不做 POSIX 模拟层**：路径/行尾/信号语义不模拟，这是与 MSYS2 的边界。
- **不新增无需求信号的命令**：新命令由用户反馈或脚本刚需触发（jq 是唯一在观察列表的候选，但属独立大项目，单独立项评估）。

## 6. 版本路线图

```
v0.5.11   文档与进度闭环收口（已完成，无 CLI 变更）
v0.5.12   发布自动化收尾（4.2）+ 基建整合（4.4）——纯内功版本
v0.6.0    分发落地（winget PR、scoop bucket、docs 站）——采用版本
v0.6.x    质量深化按批次推进（difftest 扩面 → 属性测试 → 性能基线）
1.0-rc    缺口冻结 + 全量回归 + 文档定稿
1.0       承诺冻结：CLI 行为、清单结构、发布产物签名链
```

1.0 的含义不是"功能完成"，而是**承诺冻结**：此后破坏 CLI 兼容的变更需要 major 版本，用户脚本可以放心依赖。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 单维护者（bus factor = 1） | 文档与自动化降维护摩擦；台账与门禁让任何接手者可以复现流程 |
| windows-sys 特性集冻结策略失灵 | 新 API 优先 windows_link 直声明（touch/dd/diff 已有先例）；特性新增需 Verify 全量验证 |
| 无参照工具的命令验证漂移 | 自建黄金向量 + 属性测试；文档声明参照来源 |
| 上游依赖破坏（zip/regex/clap） | 版本升级单独成轮，Verify 全量回归后再合入 |
| 清单/哈希断链复发 | check-manifests 门禁 + 发布后自动同步（4.2 落地后闭环） |

## 8. 成功的度量

- **采用**：winget 安装量、GitHub star/issue、下载次数
- **质量**：difftest 覆盖命令数与参数组合数、属性测试覆盖的解析器数、门禁红绿比
- **工程**：发布闭环人工环节数（目标：0）、Verify 时长、issue 首响应时间
- **架构**：ruxcmd-core 模块数与重复实现数（目标：归零新增）
